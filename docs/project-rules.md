# Project Rules

These rules apply to every feature.

---

Code Quality

Write production-ready code.

No placeholder code.

No TODO comments.

No fake implementations.

---

Architecture

Keep features modular.

Separate business logic.

Reusable components.

No duplicated code.

---

TypeScript

No any.

Use strict types.

Infer types when possible.

---

Validation

Validate every input.

Never trust client data.

Use Zod.

---

API

Consistent responses.

Proper status codes.

Meaningful errors.

---

Security

Sanitize input.

Protect routes.

Never expose secrets.

Rate limit sensitive routes.

---

Database

Never write raw SQL unless required.

Use Prisma.

Use transactions where needed.

---

Performance

Avoid unnecessary renders.

Paginate large datasets.

Lazy load where appropriate.

Optimize images.

---

Accessibility

Semantic HTML.

Keyboard navigation.

ARIA labels when needed.

---

Git

Small commits.

Feature branches.

Clear commit messages.

---

Testing

Test important logic.

Avoid breaking existing features.

---

Documentation

Document complex logic.

Keep docs updated.

---

AI Rules

Do not change architecture.

Do not replace libraries.

Do not introduce new dependencies without approval.

Follow tech-stack.md.

Follow database.md.

Follow phase documentation.

Ask before making major decisions.
